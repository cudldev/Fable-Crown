**User priority: preserve runtime performance.** A smaller allocation is not sufficient for acceptance. Prefer eliminating redundant copies, avoiding unnecessary rebuilds and bounded buffer reuse first. Indexed GPU lookups, packed decoding, transformed shared GI geometry and direct half-float writes are experiments until matching before/after benchmarks show no runtime regression outside repeatable measurement noise. Keep the existing path when evidence is inconclusive; do not trade responsiveness for memory savings without explicit user authorization.

## Ordered work

1. [ ] **Make the memory benchmark repeatable.** Promote the temporary audit script; record build identity, fixed fixture/camera/settings, blank baseline, main/worker allocations and DOM counts. Capture startup, warm close/overview/return and repeated travel. Distinguish live bytes, heap capacity, commitment, residency and GPU counters.
2. [ ] **Share voxel data through the GPU rendering path.** Keep one immutable voxel/color/AO dataset per asset/detail level; placements store asset index, transform and state. Replace repeated per-cell matrices/colors/AO with indexed model/placement lookup. Preserve bucket culling, LOD, depleted states, shadows, GI and reflections. Current reserve167,936cells×100bytes=16.8MB CPU attributes, plus GPU uploads; this is not the whole game footprint.
3. [ ] **Share lighting source geometry.** Send each unique model to the worker once; store object transforms/bounds/state separately and transform during local rasterization. Existing world messages already transfer buffers rather than clone them. Current240tree full/stump box lists total1.95MB; do not overstate this saving. Check rotated/scaled objects, depletion and worker cancellation.
4. [ ] **Pack immutable voxel attributes.** Use native integer coordinates and palette indices where ranges permit; decode positions/colors in the shader. Evaluate packed corner AO separately. Reuse identical capped LODs rather than rebuilding the same level. Current full/stump model data is already shared and totals1.56MB, so source packing alone has limited benefit.
5. [ ] **Benchmark removal of the full-float intermediate 3D lighting atlas.** Local grid80×16×80 uses0.819MB for albedo+emission. Packed164×16×164 RGBA atlas uses6.885MB Float32 scratch, then3.443MB half-float output; the previous3.443MB CPU field remains during replacement and GPU storage is separate. Evaluate writing interpolated values directly to half floats and copying packed gutters, saving the6.885MB intermediate per solve without changing grid resolution. Conversion inside the interpolation loop may change CPU cost; compare full solve latency and frame pacing before accepting. Validate precision, seams, AO, cancellation and transient buffer overlap; do not assume sparse storage helps this small local field. Lighting is world-position dependent and cannot simply be shared per tree asset.
6. [ ] **Reuse bounded scratch buffers and release stale allocations.** Audit model conversion, chunk capacity, GI grids/probes/atlas work and replaced resources. Pool by explicit size budgets; clear obsolete references. Verify repeated travel, lighting changes and reload/dispose do not cause retained growth.
7. [ ] **Profile UI/style allocation churn.** Measure live DOM/style data and retained objects after diagnostic collection; inspect snapshot-driven rerenders, hit targets, styles and detached nodes. Earlier87MB browser-heap capacity is not87MB of live UI. Optimize only confirmed retainers/churn while preserving keyboard/touch access.
8. [ ] **Audit render-target and asset lifetimes.** Reuse targets; release superseded reflection/shadow/frame buffers and unneeded decoded/source data. Preserve antialiasing, display density and visual defaults; do not reduce quality to claim a memory win. Account for CPU and GPU storage separately.

## Gate after each change

- [ ] Strict typecheck, relevant unit/browser tests, production build and dist/PWA base-path checks pass.
- [ ] Compare matching benchmark settings and actual screenshots: close/overview, day/dusk, both mobile orientations. Check shadows/reflections, AO, depletion and picking.
- [ ] Save/reload, deterministic gameplay, offline play and zero required external requests remain valid.
- [ ] Measure runtime separately from detailed memory tracing. Use repeated matching baseline/change/baseline trials with the same seed, camera route, settings, viewport and device; cover startup, steady play, travel/depletion, overview transitions and lighting updates. Compare mean/p95/p99 frame times, hitch counts, CPU/GPU timings where available, upload/draw costs and GI solve/apply latency. Average FPS alone is insufficient. Reused worker buffers must remain safe under cancellation/overlap.
- [ ] Record before/after commitment, residency, buffer bytes, allocation churn and timing results in `docs/PROGRESS.md`. Accept only when performance is preserved within established baseline noise and visuals remain correct; otherwise retain/revert the existing path. Desktop results do not establish physical-phone parity.

No total-memory reduction target or physical-phone result is established yet. Dedicated VRAM remains unmeasured. CPU/GPU copies are separate; sharing an asset index does not create one universal CPU/GPU allocation.
